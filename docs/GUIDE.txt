How the agent works
You will build a pipeline of six small programs that hand work to each other, with you as
the final gate before anything is submitted. Each phase in this guide builds one piece, and
each piece works on its own before you add the next.
The big idea: Claude does the thinking (matching, tailoring, answering form questions),
plain code does the plumbing (fetching jobs, saving data, driving the browser), and
nothing is ever submitted without your click.
Steps 1–4 run automatically; step 5 is you, and step 6 only touches applications you
approved.

Before you start: four things to know
These shape the design, so read them once before writing code.
1. LinkedIn and Indeed forbid bots. Their terms ban automated scraping and applying,
and they actively ban accounts. Use job APIs to find those listings, then apply on the
company's own careers page (which is usually where the "Apply" button leads
anyway).
2. Company application sites vary wildly. Greenhouse, Lever and Ashby forms are
predictable and easy to automate. Workday and custom portals need logins, multi-page
wizards and sometimes CAPTCHAs. Start with the easy three; for the rest, the agent
prepares everything and you paste it in.
3. Never let it invent experience. Tailoring means re-ordering, re-wording and
emphasizing what's true. A fabricated skill gets caught in the interview and can cost
you the offer. The prompts in Phase 4 enforce this.

import Anthropic from "@anthropic-ai/sdk";
import { z } from "zod";
import "dotenv/config";
const client = new Anthropic();
export async function askJSON<T>(system: string, user: string, schema: 
z.ZodType<T>): Promise<T> {
  const res = await client.messages.create({
    model: process.env.CLAUDE_MODEL!,
    max_tokens: 4000,
    system: system + "\nRespond with ONLY valid JSON. No prose, no code 
fences.",
    messages: [{ role: "user", content: user }],
  });
  const text = res.content.map(b => (b.type === "text" ? b.text : 
"")).join("");
  const clean = text.replace(/```json|```/g, "").trim();
  return schema.parse(JSON.parse(clean));
}
The model name above is a placeholder you can change in one place; check the current
model list in the Anthropic docs.

You tailor resumes. Rules you must never break:
1. Use ONLY facts in the candidate profile. Never add a skill, tool,
   employer, degree, date or number that is not there.
2. You may reorder sections and bullets, rewrite bullets to use the
   job's vocabulary when it describes the same thing, and drop
   less relevant items.
3. Keep it to one page (about 450 words).
4. Return a "changes" list: each edit and why it helps for this job.
5. Return "gaps": job requirements the profile cannot honestly cover.
Done when: a shortlisted job produces a clean PDF and a change list you can read in under
a minute.
Phase 5: Pre-fill the application (but never submit)
Goal: a browser bot opens the application page, fills every field, uploads your tailored
resume, takes a screenshot, and stops. The submit button is never clicked in this phase.
Add an automatic fact-check. In code, list every skill in the tailored resume and flag
any that isn't in profile.json . If anything is flagged, mark the application
needs_attention  instead of moving on. A second, cheaper Claude call asking "Does
resume B claim anything not supported by profile A?" also works well.
Render the PDF. Make one HTML resume template (plain, single column, standard
headings like Experience and Education so applicant tracking systems parse it), fill it
with the tailored JSON, and have Playwright print it: page.pdf({ path, format:
'Letter' }) . Save to output/resumes/<company>-<job>.pdf .
Optional: cover letter. Same idea, 200 words max, only when the form asks for one.
Start with Greenhouse only. Its forms use the same field names at almost every
company, so one script covers hundreds of employers. Add Lever and Ashby after it
works.
Step 1 — read the form. Open apply_url  with Playwright in visible mode ( headless:
false ) and collect every input: its label, type (text, select, checkbox, file), options and
whether it's required.
Step 2 — let Claude answer. Send Claude the field list, profile.json  (including
standard_answers ) and the job description. Ask for { field_id, value,
confidence, source }  per field, where source  says which profile fact the answer
came from. Tell it: "If the profile doesn't contain the answer, return null and confidence
0. Never guess."

Phase 6: The approval queue
Goal: one local web page where you see each ready application and choose Approve, Edit,
or Reject. This is your "waits for my approval" step.
Step 3 — fill it. For each answer: page.fill()  for text, page.selectOption()  for
dropdowns, page.check()  for checkboxes, page.setInputFiles()  for the resume
PDF. Leave null answers empty.
Step 4 — capture and stop. Save a full-page screenshot, store the answers in
applications.form_answers , set status to awaiting_review , and close the browser
without clicking submit.
Add a code-level safety lock. In fill.ts , refuse to ever call .click()  on any element
whose text matches /submit|apply|send/i . The only code allowed to submit lives in
Phase 7 and needs an approved record.

Phase 7: Submit, track and follow up
Goal: approved applications get submitted, and you always know where each one stands.
Done when: one application goes all the way from search to submitted, and shows up in
your tracker.
Guardrails and what to build next
Keep these on the whole time:
Approve sets status to approved  and records approved_at . Reject sets rejected
with an optional reason; feed those reasons back into your Phase 3 prompt over time.
Run it with npm run dev  and open localhost:3000/queue . Keep it local — it shows
your personal data, and you haven't added login.
Write submit.ts . It only loads applications with status = 'approved' . For each one
it re-opens the form, re-fills it from the saved (possibly edited) answers, takes a final
screenshot, and then clicks submit.
Recommended for your first few weeks: skip the auto-click. Have submit.ts  open
the filled form in a visible browser and let you press Submit. You'll catch form quirks
the bot missed, and the extra 5 seconds per job is worth it.
Confirm success. After submitting, check for a confirmation message or URL change.
Found → status submitted  with submitted_at . Not found → needs_attention , never
assume it worked.
Track outcomes. Add outcome  values: no_response , rejected , interview , offer .
Update them from the queue page as emails come in.
Follow-up reminder. A tiny query lists applications submitted 10+ days ago with no
response, so you can send a short follow-up note if you have a contact.
Run the pipeline in order with one command, e.g. npm run daily  → search → score →
tailor → fill. Then open the queue with your coffee.
Nothing is submitted unless its record says approved , set by you in the queue.
Tailored resumes pass the fact-check against profile.json .
Unknown form answers stay empty; the bot never guesses.
CAPTCHAs, logins and account creation are always handed to you.
